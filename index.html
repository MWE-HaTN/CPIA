Part 4
Common Confusions Consolidation
All "Common Confusion" notes from across the guide, collected into one reference sheet.

Crypto Confusions

  • Base64 is encoding (no key) — not encryption (requires key).
  • Hashing is one-way — not encryption (reversible with correct key).
  • HMAC is not just a hash — it includes a shared secret with a two-pass construction (inner / outer padding).
  • RSA is asymmetric — used for key exchange and signatures, not bulk data encryption.
  • AES is symmetric — used for bulk data encryption.
  • Hybrid encryption: encrypt data with AES, encrypt the AES key with RSA.
  • For evidence: compute at least SHA-256; MD5 may be included for tool compatibility only.

Timestamp Confusions

  • NTFS stores timestamps in UTC — but tools may display local time.
  • FAT stores timestamps in local time — ambiguous without timezone context.
  • Modified means file content changed.
  • Changed means NTFS $STANDARD_INFORMATION metadata changed (e.g., rename, permission, ownership).
  • Clock skew must be documented, not silently corrected.
  • Born / Created later than Modified is suspicious but not definitive — legitimate backup restoration can also create this pattern.
  • Identical MACB values across multiple files can indicate timestamp manipulation, although legitimate mass-copy operations can also create patterns.

Forensic Evidence Confusions

  • Prefetch proves execution; Shimcache proves file existence — Shimcache does not reliably prove execution on all Windows versions.
  • USB artefact proves connection — file access or exfiltration requires additional correlation.
  • Hash-based IoCs change with one byte — behavioural IoCs (TTPs) are more robust.
  • VirusTotal detection ratio is context, not proof — 1/70 may be a false positive or targeted malware; 40/70 usually indicates known malware.
  • AV names are not standardised across vendors — interpret with caution.

Firewall / ACL Confusions

  • Rule order matters — first matching rule usually decides the action.
  • NAT is not a security control — it changes addressing; does not replace filtering or logging.
  • Ingress and egress are both important — blocking inbound attacks does not stop outbound C2.
  • IPv6 not filtered — dual-stack hosts bypass IPv4-only controls.
  • When a rule appears correct but traffic still passes — check rule order, object groups, NAT, interface direction, IPv6, and shadowed rules.

Network Confusions

  • IDS = detect / alert (passive); IPS = detect / prevent (inline).
  • NetFlow = flow summaries (no payload); PCAP = full packets.
  • JA3 = TLS client fingerprint — helps identify malware families but is not definitive attribution.
  • WPA2 is not automatically secure — depends on passphrase strength, WPS status, and enterprise authentication config.
  • TLS 1.2 / 1.3 preferred — SSLv2 / v3 and TLS 1.0/1.1 are obsolete.

ATT&CK Confusions

  • One technique can map to multiple tactics depending on intent (e.g., Scheduled Task = Execution or Persistence).
  • Hashes and IP addresses are easy to block but easy for attackers to change. Behavioural IoCs are more robust.
  • Credential Access ≠ Privilege Escalation — different tactics even though they can be related.

Acquisition Confusions

  • Volatile evidence first: CPU registers / cache → RAM → network state → running processes → disk → archival media → remote logging.
  • HPA / DCO can hide disk areas — forensic tools should detect and document them.
  • SSD TRIM and wear levelling affect deleted-data recovery.
  • Static acquisition = powered off; Live acquisition = running system.
  • Documentation is not optional admin work — it is part of evidential integrity.

ACPO / NPCC 4 Principles

  1. Do not alter data that may be relied upon in court.
  2. If original data must be accessed, the person must be competent and able to explain actions.
  3. Maintain an audit trail sufficient for an independent examiner to reproduce the result.
  4. The case officer has overall responsibility for compliance with law and principles.

Exam Traps to Memorise

#TrapCorrect exam logic
1Volatile evidence firstCollect RAM, network state, running processes, and open handles before disk-only artefacts when safe and within scope.
2Do not alter evidence unnecessarilyDo not delete malware, reboot, power off, or change systems unless justified for containment and fully documented.
3Legal / client escalationConsult client / legal before involving third parties, except mandatory escalation cases such as CSAM or explicit legal duty.
4Read inverted MCQ wordingWatch for NOT, LEAST, EXCEPT, FIRST, BEST, and MOST APPROPRIATE. CPIA often tests judgement order.
5Base64Encoding, not encryption. No key is required. Decode first, then analyse the decoded content.
6HashingHashes are one-way fingerprints, not encryption. You compare, verify, or crack / brute-force hashes; you do not decrypt them.
7MD5 vs SHA-256MD5 is weak for strong integrity assurance but still useful for quick triage and tool compatibility. Prefer SHA-256 for evidence integrity.
8IoC strengthHash / IP / domain IoCs are precise but fragile. Behavioural IoCs and TTPs are more resilient but require context.
9IP address attributionIP address alone is not identity. Correlate DHCP lease time, NAT translation, hostname, user logon, and endpoint activity.
10Windows Logon TypesRDP is Logon Type 10. SMB / network access is Type 3. Local console login is Type 2. Do not confuse them.
11IDS alertAn IDS alert is not proof of compromise. Validate payload, direction, vulnerable target, context, and follow-on activity.
12VirusTotalVirusTotal is context, not proof. 0 detections does not mean safe; client consent is required before uploading sensitive samples.
13Prefetch vs ShimcachePrefetch is stronger evidence of execution. Shimcache / Amcache support presence / execution context but should be corroborated.
14pslist vs psscanpslist walks active process lists. psscan scans memory pools and may reveal hidden or terminated processes.
15MACB timestampsModified = content change. Changed = NTFS metadata change. Born later than Modified is suspicious, not absolute proof; corroborate with other artefacts.
